# Pi ハーネス学習教材

このリポジトリの Pi ハーネスを、**自分で理解して、自分で直せるようになる**ための教材です。

- 何がどう実装されているか(ファイル・関数・イベント)
- **なぜ**その実装にしたのか(却下した案、トレードオフ)
- **Claude Code ではどうなっているか**(比較)
- 手を動かす演習

## この教材の読み方

1. まず、この README の「全体像」と「用語」を読む(15 分)
2. [01 インストールして動かす](01-install-and-run.md) で、実際に動かす
3. [02 Pi の基礎](02-pi-basics.md) で、土台の概念をつかむ
4. 03 以降は、気になる章から読んでよい(各章は独立している。ただし 07 は 03・06 を先に読むと分かりやすい)

## 全体像

### このハーネスは、何をするものか
Pi は、AI コーディングエージェントの**土台**です。権限の確認も、サブエージェントも、計画も、標準では持ちません。このハーネスは、**Pi の拡張**として、次を足したものです。

| 層 | やること | 章 |
|---|---|---|
| **止める** | 危険な操作を、仕組みで拒否する(Git、削除、インストール、秘密情報) | 03 |
| **渡す** | 日本語の固定の指示を、毎回渡す。最終行を決まった形にする | 04 |
| **選ぶ** | モデルを選ぶ。利用状況を見せる | 05 |
| **任せる** | サブエージェントに作業を任せる | 06 |
| **回す** | 計画を立て、完了まで止まらずに進める | 07 |
| **確かめる** | 検証・独立レビュー・PR・マージを、ゲートつきで行う | 08 |
| **残す** | 会話の要約で、大事な状態を残す。設定を配置する | 09 |

### 基本方針: ルールは、コンテキストではなく、ハーネスで強制する
「`main` に直接 push しない」を、AI への**お願い**(`AGENTS.md` や `CLAUDE.md` に書く)で済ませると、守られるかが毎回ぶれます(非決定論)。このハーネスは、**お願いに頼らず、コードで止めます**(決定論)。

ただし、**判断が要るもの**(言語、任せ方、レビューの観点)は、コードでは決められないので、固定の指示として渡します。つまり、ルールを 3 つに分けています。

1. **仕組みで止める**: コードで強制する(拒否する)
2. **流れとして組み込む**: コードで、順序と条件を決める(計画 → 検証 → レビュー → PR)
3. **固定の指示として渡す**: 文章で渡す(守られるかは、モデルしだい)

### 1 回の依頼で、何が起きるか(流れ)
```
ユーザーが入力
  │  input イベント ──→ (output) 「今回の依頼」の状態をリセット
  │  before_agent_start ──→ (instructions) 固定の指示を <harness> セクションに追加
  │                          (flow) 確定済みの計画があれば <harness_plan> も追加
  ▼
モデルが応答(ツール呼び出しを含む)
  │  tool_call ──→ (guards) 検査。block なら実行されず、理由がモデルに返る
  │  ツール実行
  │  tool_result ──→ (guards) 出力の秘密を秘匿
  │  message_end ──→ (output) 最終応答なら、最後の 1 行を「🚀作業が完了しました！」に
  ▼
モデルが、ツール呼び出しなしで応答を終える
  │  agent_before_settle ──→ (flow) 計画に未完了があれば「続けて」と継続を要求
  │       ↑___________________________|  (継続のたびに、上の流れに戻る)
  ▼
agent_settled(本当の終わり)
```
`(guards)` などは、`agent/extensions/harness/` の下のディレクトリ名です。

### 設計の核: 「純粋な部分」と「接続する部分」を分ける
このハーネスのコードは、2 種類に分かれます。

- **純粋な関数**(入力 → 出力。Pi を使わない): `shell.ts`、各ガード、`plan.ts`、`loop.ts`、`pr.ts` など。**テストしやすく**、将来ほかのエージェントに移すときも**再利用できる**。
- **接続する部分**(`register.ts`): Pi の API(`pi.on`、`registerTool` など)に接続する。薄く保つ。

コードを読むときは、**まず純粋な関数を読み、次に `register.ts` で、どこから呼ばれるかを見る**と、理解しやすいです。

## Claude Code との対応表(早見表)

| やりたいこと | Claude Code | Pi | このハーネス |
|---|---|---|---|
| 設定の置き場所 | `~/.claude`、プロジェクトの `.claude/`、管理者の設定(4 つの範囲) | `~/.pi/agent`、プロジェクトの `.pi/` | `agent/` を `~/.pi/agent` にリンク |
| 拡張の仕組み | **フック**(外部コマンド・HTTP・プロンプト・エージェントを、イベントで呼ぶ) | **拡張**(TypeScript のモジュール。プロセスの内部で動く) | 拡張 1 つ(`harness`) |
| ツール実行の前に止める | `PreToolUse` フック(終了コード 2、または `permissionDecision: "deny"`)。権限ルール | `tool_call` フックで `{ block: true }` | `guards/` |
| 権限の確認 | 権限モード、`allow` / `ask` / `deny` のルール(優先順位: deny → ask → allow) | 組み込みなし | `Verdict`(allow / ask / block)。ask は確認、UI なしなら拒否 |
| 指示を渡す | `CLAUDE.md`、`.claude/rules/`、`SessionStart` フックの `additionalContext` | `AGENTS.md`、システムプロンプトのセクション | `<harness>` セクション |
| 出力を加工 | `PostToolUse` フック | `tool_result` フック | 秘密の秘匿 |
| 止まらず続ける | `Stop` フック(終了コード 2 / `decision: "block"` で、続ける)、`/goal` | `agent_before_settle` で `continue: true` | 計画のループ |
| 要約を制御 | `PreCompact` フック(標準出力が、要約への指示になる)、`/compact` の引数 | `session_before_compact` で、要約を差し替え | 要約 + 確定した状態 |
| サブエージェント | 組み込み(`Agent` ツール、`.claude/agents/*.md`) | 組み込みなし | `subagent` ツール(別プロセス) |
| スラッシュコマンド | `.claude/commands/*.md`(未確認) | `registerCommand`、プロンプトテンプレート | `/models`・`/plan` など |
| スキル | `SKILL.md`(未確認) | `SKILL.md`(同じ形式) | `nix-setup` |
| サンドボックス | bubblewrap / Seatbelt(組み込み) | 組み込みなし | **未実装** |

## 用語集

| 用語 | 意味 |
|---|---|
| ハーネス | AI モデルの周りに作る、道具・ルール・流れの全体 |
| エージェントループ | 「モデルが応答 → ツールを実行 → 結果をモデルに返す」の繰り返し |
| ターン | モデルの 1 回の応答と、そのツール実行 |
| フック / イベント | 流れの途中に、自分のコードを差し込める場所 |
| ツール | モデルが呼べる機能(`bash`、`read`、`edit`、自作のもの) |
| fail-closed | 判断できない・エラーのときに、安全側(拒否)に倒す |
| 決定論 | 同じ入力なら、必ず同じ結果になる |
| 指紋(fingerprint) | 作業ツリーの内容から作る値。変更があったかを調べる |
| ゲート | 条件を満たさないと通れない関門(完了・マージのゲート) |
| 継続 | モデルが終わろうとしたとき、ハーネスが「続けて」と、もう 1 回動かすこと |
