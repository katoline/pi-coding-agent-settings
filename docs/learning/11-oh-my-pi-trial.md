# 11 oh-my-pi(OhmyPy)を試す

## ねらい
ゼロからハーネスを作るのは、ハードルが高い。まず **oh-my-pi** を試し、「出来合いの、多機能な Pi 系のエージェントは、どういうものか」を体験します。そのあと、**このハーネスと比べる**ことで、各機能の「なぜ」が、より分かるようになります。

> **確かさについて:** この章の oh-my-pi の情報は、**公式 README(`can1357/oh-my-pi`、2026-11-13 に取得)**に基づきます。細部(各機能の挙動、Pi の拡張との互換性)は、**私は、実機で動かしていません**。分からないことは、「未確認」と書きます。

## oh-my-pi とは
- 名前: **oh-my-pi**、コマンドは **`omp`**。開発元は Stencil Labs(`can1357`)。
- **Pi(Mario Zechner の `pi-mono`)の、フォーク**。README は、「Pi を土台に、コーディング向けに作り直した」と説明しています。**Pi 本体とは、別のプロジェクト**です(パッケージ名は `@oh-my-pi/pi-coding-agent`。このリポジトリが使う `@earendil-works/pi-coding-agent` とは別物)。
- 設定は、**`~/.omp/agent/`**(Pi の `~/.pi/agent` とは、別)。

### 公式 README が挙げる主な機能
| 機能 | 内容 |
|---|---|
| サブエージェント | `task` ツールで、作業を分担。**隔離した worktree** にもできる。結果は、スキーマで検証 |
| LSP | 診断、定義へのジャンプ、リネーム、コードアクション(14 の操作) |
| デバッガ | DAP で、ブレークポイント、ステップ実行、変数の確認(28 の操作) |
| ストリームのルール | 出力が、正規表現に一致したら、ストリームを**中断**し、ルールを差し込んで、**やり直す** |
| アドバイザー | **別のモデル**が、各ターンをレビューして、メモを差し込む |
| MCP | プロジェクトの MCP 設定を読み込む |
| 拡張 | TypeScript のモジュール。ビルトインと、**同じ API** |
| そのほか | メモリ、Web 検索(25 のバックエンド)、ブラウザ・デスクトップの操作、エディタ連携(ACP)、SDK、RPC モード、セッション共有(`/collab`) |
| プロバイダ | 60 以上。**Anthropic と OpenAI Codex は OAuth ログイン**に対応。**OpenCode Go** も「coding plans」に載っている(ログイン手順は、README には書かれていない) |

## インストール(試す手順)
公式が挙げる方法のうち、このあたりが現実的です。

```bash
# 推奨: bun で入れる(bun ≥ 1.4.4 が必要)
bun --version
bun install -g @oh-my-pi/pi-coding-agent
omp --version
```
- bun が古い・入っていないときは、先に bun を更新する(`bun upgrade`、または公式のインストール手順)。
- ほかの方法: シェルのインストーラー(`curl -fsSL https://omp.sh/install | sh`。**実行前に、スクリプトの中身を、ダウンロードして読む**ことをおすすめします)、Homebrew、Nix、mise。
- バージョンを固定するなら、インストーラーに `--ref v<バージョン>`。

**このハーネスの方針との関係:** [01](01-install-and-run.md) では、「Pi は、版を固定して入れ、拡張は、導入前にソースを読む」としました。**oh-my-pi も、同じ注意が必要**です(更新が速い可能性、巨大なコードベース、**実行ファイルを入れる**)。まず、**使い捨てのディレクトリ**(重要なファイルのない場所)で、試してください。

## 試すときの、安全のための 5 つの注意
1. **サンドボックスは、ない**(README に、シェルやデスクトップ操作の、サンドボックスの記載がない)。このハーネスと同じく、**ホストで、そのまま動く**。
2. **リポジトリを開くと、その中の設定・拡張・フック・ツール・コマンド・スキル・ルール・MCP 設定を、読み込む**(README の「信頼」の項)。**知らないリポジトリでは、開かない**。使うなら、次のフラグで、読み込みを絞る。
   - `--no-extensions`: 拡張の自動検出を、止める
   - `--trusted-extension <パス>`: 指定した拡張だけを許可
   - `--config`: YAML で、`mcp.enableProjectConfig: false` などを上書き
   - README は、これらは「**リポジトリの信頼のモデルを、変えない**」と書いている(読み込みを、絞るだけ)
3. **API キーは、使い捨ての範囲で**。最初は、OAuth ログイン(`/login`)を使い、**課金の上限が、あるアカウント**で試す。
4. **画面操作・ブラウザ操作・デスクトップ操作**の機能は、最初は、**使わない**。
5. このリポジトリの設定(`~/.pi/agent`)と、oh-my-pi の設定(`~/.omp/agent`)は、**別**。混ぜない。

3. **サブエージェント(`task`)**: 「調査を 2 つに分けて、並列で」と頼む。このハーネスの `subagent`([06](06-subagents.md))と、**表示・結果の形・費用**を比べる。
4. **LSP・デバッガ**: ある言語の小さなプロジェクトで、診断やリネームを、試す。**このハーネスには、ない機能**。
5. **ストリームのルール**と**アドバイザー**: どう設定し、**どんなときに、介入するか**を見る。[04](04-instructions-and-output.md)(指示)や [08](08-verify-review-pr.md)(レビュー)と、比べる。
6. **権限の確認**: `git push --force` や、`rm -rf` を頼んで、**止まるか・確認されるか**を見る。[03](03-guards.md)と比べる。**ここが、いちばん大事な比較**です。
7. **自律ループ**: 長い作業を頼んで、**終わるまで進むか**を見る。[07](07-plan-and-loop.md)と比べる。

## このハーネスと、oh-my-pi の関係
- **互換性は、未確認**です。oh-my-pi は、**Pi のフォークで、API が、同じとは限りません**。README は、**Pi 用の拡張を、そのまま読み込めるか**に、触れていません。このハーネスの拡張(`agent/extensions/harness`)が、そのまま動くかは、**試さないと分かりません**。
- 試すなら、**別の使い捨てのディレクトリ**に、拡張を置き(`~/.omp/agent/extensions/` など。**場所は、公式ドキュメントで確認**)、**読み込めるか**、`/reload` などで、確かめます。**動かなくても、問題ありません**(それが分かること自体が、結果)。
- このハーネスの**純粋関数**(シェルの解析、ガード、計画の状態機械、ループの判断、PR のゲート)は、**Pi に依存しません**([README](README.md))。oh-my-pi の拡張として、**接続部分(`register.ts`)だけを、書き直せば**、再利用できる可能性があります(**未検証**)。

## どう使い分けるか(私の見立て)
- **oh-my-pi を、そのまま使う**: 機能が多く、**すぐ始められる**。LSP やデバッガなど、**コードの理解に強い**機能がある。ただし、**ルールの強制**(あなたの 3 つのルール)が、どこまでできるかは、**試して確認**する必要がある。
- **このハーネスを使う**: **ルールの強制と、完走する自律ループ**を、**自分で、細かく制御**できる。ただし、**サンドボックスが未実装**で、機能は、少ない。
- **両方の良いとこ取り**: oh-my-pi を試して、**足りない強制(ガード・ゲート)を、拡張として足せるか**を、見る。足せるなら、このハーネスの純粋関数を持ち込める。

どれにするかは、**試したあと**に、決めるのがよいです。結果は、[../open-questions.md](../open-questions.md) に、書き足してください。
