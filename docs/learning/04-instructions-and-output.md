# 04 固定の指示と最終行: 「渡す」と「書き換える」

## ねらい
コードで強制できないルール(言語、任せ方、レビューの観点)を、**ハーネスが毎回渡す**仕組みと、**モデルの書き忘れに頼らず、出力の最後の 1 行をハーネスが書き換える**仕組みを理解します。

## 何を作ったか
| ファイル | 役割 |
|---|---|
| `instructions/main.md` | メインエージェントへの固定の指示(日本語) |
| `instructions/subagent.md` | サブエージェントへの固定の指示 |
| `instructions/load.ts`(23 行) | md を読み込み(キャッシュ)、役割の指示を足す |
| `instructions/register.ts`(21 行) | `before_agent_start` で、システムプロンプトに `<harness>` セクションを足す |
| `output/final-line.ts`(50 行) | 最終行を足す純粋関数 `withFinalLine` |
| `output/register.ts`(42 行) | いつ付けるかを判断し、`message_end` で置き換える |

## 仕組み

### A. 固定の指示
```ts
pi.on("before_agent_start", async (event) => {
  const options = event.systemPromptOptions;
  const text = composeInstructions(rt.isSubagent ? "subagent" : "main");
  options.sections = { ...(options.sections ?? {}), harness: text };
});
```
- Pi のシステムプロンプトは、**名前つきのセクション**の集まりです。ハーネスは、`harness` というセクションを足します(全体を置き換えません)。
- メインとサブエージェントで、**違う md** を渡します(`rt.isSubagent`)。サブエージェントには、役割ごとの指示(`agents/*.md` の本文)も足します。
- 設定 `dropContextFiles: true` にすると、プロジェクトの `AGENTS.md` / `CLAUDE.md` を、モデルに渡さなくできます(既定は false)。

`main.md` の中身は、**ルールの 3 分類**でいう「固定の指示」です。
- 言語(日本語)
- 進め方(Plan → Do → Check → Act。計画の確定までは、ユーザーに質問し、確定後は質問しない)
- 自律実行のルール(テストを skip して通すのは禁止、など)
- サブエージェントへの任せ方
- レビューの範囲(外部に晒される部品は攻撃者がいる前提、など)

ここに書いたことは、**モデルが守るかは、保証されません**。守らせたいものは、ガード([03](03-guards.md))や、フロー([07](07-plan-and-loop.md)、[08](08-verify-review-pr.md))に移します。たとえば「テストを skip して通すのは禁止」は、指示に書いてあるだけで、コードでは止めていません(**限界**を参照)。

### B. 最終行
「作業が完了したら、最後の 1 行を `🚀作業が完了しました！` にする」を、**モデルに頼まず**、ハーネスが保証します。

```
tool_execution_end ─→ 成果物を作る操作があったら rt.run.touched = true
                       (write / edit / harness_pr_create / harness_pr_merge / harness_worktree、
                        bash の git commit)
message_end ─→ (touched または計画の完了) かつ 未完了の項目が 0 なら、
               最終応答の最後に「🚀作業が完了しました！」を足す
input ─→ 新しい依頼のたびに、rt.run をリセット
```
`withFinalLine` が付けない場合(純粋関数。テストされている): ツール呼び出しを含むメッセージ(まだ続く)、エラーや中断のメッセージ、すでに最終行があるとき。サブエージェントには付けません。

## なぜこう実装したか
| 選んだこと | 却下した案 | 理由 |
|---|---|---|
| **指示を、`AGENTS.md` ではなく、ハーネスから渡す** | `~/.pi/agent/AGENTS.md` に書く | ハーネスと指示を**1 つのリポジトリで管理**でき、プロジェクトの `AGENTS.md` と**混ざらない**。サブエージェントと、役割で、**出し分け**られる |
| **セクションを足す(置換しない)** | システムプロンプト全体を、置き換える | Pi の標準の部分(ツールの説明など)や、他の拡張と共存できる。更新にも追従できる |
| **指示を md ファイルにした** | TypeScript の文字列にする | 文章は、編集しやすい形で。差分も見やすい |
| **最終行を、`message_end` で書き換える** | 指示に「最後の 1 行は〜」と書く | 書き忘れ・言い回しの揺れが、起きる。決まった形が要る(人間も、ほかのツールも、機械的に読める)なら、コードで保証する |
| **「完了」の条件を、成果物と未完了項目で判断する** | いつでも付ける | 質問への返答や、調べものにまで「作業が完了しました」を付けると、意味が薄れる。**何かを作り、残りがないとき**に限る |
| **確定したメッセージを置き換える(`message_end`)** | 次の依頼で、追記する | 表示される内容と、保存される内容が、同じになる |

## Claude Code では
| 観点 | Claude Code | このハーネス |
|---|---|---|
| 固定の指示 | **`CLAUDE.md`**(ユーザー・プロジェクト・ローカル)と **`.claude/rules/`**。起動時に読み込まれる(公式ドキュメントで確認) | `<harness>` セクション(拡張から) |
| 動的に足す | **`SessionStart` フックの `additionalContext`**、`UserPromptSubmit` フックの追加コンテキスト | `before_agent_start`(毎回) |
| システムプロンプトの変更 | CLI の `--append-system-prompt` などのオプション(**未確認:** 細部) | セクション単位で、足せる |
| 守らせ方 | `CLAUDE.md` は、**コンテキスト**であり、強制ではない。公式も、「指示として渡すもの」と位置づけている(**未確認:** 文言) | 同じ(指示は非決定論)。強制したいものは、ガード・フローに分ける |
| 出力の書き換え | 最終応答の書き換えフックは、**見つからなかった**(未確認)。`Stop` フックで、「続けて」と、追加の応答を促すことはできる | `message_end` で、確定したメッセージを置き換え |
| 完了の確認 | `Stop` フック、`/goal`(評価モデルが、条件が満たされたかを判定する) | 計画のゲート([07](07-plan-and-loop.md)) |

**違いの要点:**
- 「指示を渡す」は、両方にある(`CLAUDE.md` と `<harness>` セクション)。違いは、**置き場所と出し分け**。Claude Code は、ファイルの階層(ユーザー / プロジェクト / ローカル)で、**人が書くもの**。このハーネスは、**コードから、役割ごとに出し分ける**。
- Claude Code で、同じことをするなら、`SessionStart` フックで、指示を `additionalContext` として渡す方法が近い。
- 「最終行を保証する」は、Claude Code の標準機能では、**直接はできない**(未確認)。代わりに、`Stop` フックで、「最後に〜を書いていないなら、書かせる」と、再実行させる形になる。**モデルがもう 1 回動く分、遅く、費用がかかり、確実さも下がる**。Pi は、確定する瞬間に、コードで書き換えられる。

## 試してみよう
1. `instructions/main.md` の「言語」を、英語に変えて `/reload` → 新しい依頼で、応答の言語が変わるかを見る。元に戻す。
2. `tests/final-line.test.ts` を読み、「付けない場合」を、全部挙げる。1 つ足してみる(たとえば、本文が空のとき)。
3. 最終行の文言を、`output/final-line.ts` の `FINAL_LINE` で変え、`npm test` を実行する → **テストが、何を守っているか**が分かる。
4. 試用環境で「README.md を作って」と頼み、最後の行を観察する。次に、「Git とは何か、説明して」と頼み、**最終行が付かない**ことを確かめる。

## 限界と注意
- **指示は、非決定論**: `main.md` の「テストの skip は禁止」などは、**守られる保証がない**。ガードやゲートに移す余地がある(`.skip` を差分から検出して、ゲートで止める、など)。
- 最終行は、**何かを作ったとき**だけ付く。`bash` で、ファイルを書いた(`echo > file`)場合は、`touched` にならない(`git commit` だけ見ている)。
- 指示が長いと、毎回のトークンを消費する。`main.md` は、約 40 行。**増やすほど、守られにくくなる**ことも、よく知られている(未確認:定量的な根拠はない)。
