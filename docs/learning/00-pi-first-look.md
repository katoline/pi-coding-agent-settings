# 00 Pi を入れた直後の姿: できること、設定の置き場所、プログラムの書き場所

初めて Pi を触る人のための章です。ハーネスを一から作る前に、**素の Pi が、何を持っていて、何を持っていないか**、**どこに何を置けばよいか**を、整理します。

> **出典:** Pi 1.5.2 に同梱の公式ドキュメント(`node_modules/@earendil-works/pi-coding-agent/docs/` の `how-pi-works.md`、`quickstart.md`、`usage.md`、`configuration.md`、`settings.md`、`security.md`、`slash-commands.md`、`cli.md`、`skills.md`、`prompt-templates.md`、`extensions.md`、`providers.md`、`models.md`、`packages.md`)と、`dist/core/system-prompt.js`(既定のシステムプロンプトの実装)。**読んだ内容だけを書いています。** 実機で、すべてを動かして確かめたわけではありません。

## 1. Pi とは何か(一言で)

端末(ターミナル)で動く、**コーディング用の AI エージェント**です。自分のマシンのファイルを、**読む・編集する・コマンドを実行する**ことができます。
中身の基本は、次の繰り返しです(`how-pi-works.md`)。

```
あなたが依頼を入力
  → Pi が「システムプロンプト + これまでの会話 + 使えるツールの一覧」をモデルに送る
  → モデルが、文章 と/または ツール呼び出しを返す
  → Pi がツールを実行し、結果を記録して、モデルに返す(これで 1 ターン)
  → ツール呼び出しがなくなれば、終わり
```

用語を 3 つだけ覚えます。
| 用語 | 意味 |
|---|---|
| **プロバイダ** | モデルを使うための、サービスやアカウント(Anthropic、OpenCode Go、OpenAI/Codex など) |
| **モデル** | 応答を作る AI 本体(`claude-sonnet-5-5` など) |
| **セッション** | 1 つの会話の記録。ファイル(JSONL)として、自動で保存される |

## 2. 入れた直後に、できること(既定の仕様)

### 2.1 起動と基本操作
```bash
cd 作業したいフォルダ
pi
```
- **起動したフォルダ**が、作業の基準になります(設定・指示ファイルの探索、`@ファイル` の解決、セッションのグループ分けに使われる)。
- 画面は、会話の表示 + 入力欄 + 下のステータス(フォルダ、モデル、文脈の使用量、累計の使用額)。

| やりたいこと | 操作 |
|---|---|
| 送信 / 改行 | `Enter` / `Shift+Enter` |
| ファイルを指定 | `@` を打って検索 |
| シェルのコマンドを自分で実行 | `!git status`(結果が会話に入る)。`!!` なら、結果をモデルに渡さない |
| 作業中に、方向を変える | 作業中に入力して `Enter`(次の応答への指示)/ `Alt+Enter`(今の作業が終わってから) |
| 止める | `Esc`(送信待ちの入力は、入力欄に戻る) |
| ツールの出力を開閉 | `Ctrl+O` |
| 考え中の表示を開閉 | `Ctrl+T` |
| 思考の深さを切り替え | `Shift+Tab` |
| ショートカットの一覧 | `/hotkeys` |

### 2.2 既定のツール(モデルが使える道具)
**既定で有効なのは 4 つ**です(`settings.md` の `defaultTools`)。
| ツール | できること |
|---|---|
| `read` | テキストファイルと画像を読む |
| `bash` | シェルのコマンドを実行する |
| `edit` | 既存のファイルの、決まった文字列を置き換える |
| `write` | ファイルを作る・上書きする |

**既定では無効**だが、有効にできるもの: `grep`(検索)、`find`(ファイル探し)、`ls`(一覧)、Windows 用の `powershell`。
さらに、**組み込みの拡張**が 2 つのツールを持っています: `codemode`(JavaScript で、複数のツールを並列に呼ぶ)、`tool_search`(未宣言のツールを検索)。これらも、既定ではオフです。

有効にするには、`settings.json` の `"defaultTools"`、または起動時の `--tools` を使います(例: `pi --tools read,grep,find,ls` で、**読み取り専用**にできる。このハーネスの `scout` / `reviewer` が、この方式)。

### 2.3 組み込みのスラッシュコマンド(`/slash-commands.md`)
| 種類 | コマンド |
|---|---|
| モデルと設定 | `/settings`、`/model`、`/thinking`、`/scoped-models`、`/login`、`/logout` |
| セッション | `/new`、`/resume`、`/name`、`/session`、`/tree`、`/fork`、`/clone`、`/compact`、`/import` |
| 出力・共有 | `/copy`、`/export`、`/share`、`/bug` |
| 実行環境 | `/trust`、`/mcp`、`/reload`、`/hotkeys`、`/changelog`、`/quit` |

`/` を打てば、**今のセッションで使えるコマンドの一覧**が出ます(拡張・スキル・テンプレートが足したものも含む)。

### 2.4 セッション
- **自動で保存**されます(`~/.pi/agent/sessions/` の下に、作業フォルダごと)。`--no-session` なら、保存しない。
- `pi --continue`: そのフォルダの、直近のセッションを再開。`/resume`: 選んで再開。
- **木構造**で、過去に戻って、別の道を試せます(`/tree`、`/fork`、`/clone`)。元の道は消えない。
- 会話が長くなると、**自動で要約**されます(compaction)。`/compact` で、手動でも。元の記録は、消えない。

### 2.5 使い方の種類(インターフェース)
| 方法 | コマンド | 用途 |
|---|---|---|
| 対話(TUI) | `pi` | 人が使う |
| 1 回きり | `pi -p "要約して"`(`--print`) | スクリプト、パイプ(`git diff \| pi -p "レビューして"`) |
| JSON | `pi --mode json` | イベントを JSONL で出す |
| RPC | `pi --mode rpc` | ほかのプログラムから、標準入出力で操作する(**このハーネスの統合テストが使っている**) |
| SDK | TypeScript から | プログラムに、組み込む |

### 2.6 モデルの接続
- `/login` で、プロバイダを選び、**ブラウザのログイン(OAuth)**か、**API キーの保存**をします。保存先は `~/.pi/agent/auth.json`。
- 環境変数でも渡せます(`ANTHROPIC_API_KEY`、`OPENCODE_API_KEY`(Zen と Go 共通)など)。CI などで便利。
- ローカルのモデルや、互換のエンドポイントは、`models.json` で追加します。

## 3. 入れた直後に、**ないもの**(ここが大事)

公式ドキュメントから、はっきり読み取れることです。

| ないもの | 根拠(公式) |
|---|---|
| **権限の確認** | 「Pi は、ツール呼び出しのたびに、確認を求めません」(`quickstart.md`、`usage.md`、`security.md`) |
| **サンドボックス** | 「ビルトインのサンドボックスがない」ことは、**セキュリティ上の想定内**(`security.md`)。守りたいなら、コンテナ・VM などを、自分で用意する |
| **計画機能・自律ループ・サブエージェント** | 組み込みの機能としては、書かれていない(拡張で作る。`examples/extensions/` に、`plan-mode`、`todo`、`subagent` などの**サンプル**がある) |

つまり、**素の Pi は、「ツールを持ったエージェントのループ」だけ**で、**ルールや安全の仕組みは、自分で足す**前提です。これが、このリポジトリのハーネスが存在する理由です。

> 補足: 公式ドキュメントは、**プロジェクトを開いたときの信頼(project trust)**という仕組みを持っています(次の 4.3)。ただし、これは「**何を読み込むか**」の制御で、**ツールが何をできるか**の制限ではありません。

### 既定のシステムプロンプト(`dist/core/system-prompt.js`)
素の Pi が、モデルに渡す指示は、**短い**です。
- 冒頭: 「あなたは、pi というコーディングエージェントのハーネスの中で動く、コーディングアシスタントです。ファイルの確認、コマンドの実行、コードの修正を手伝います」
- 使えるツールの一覧と、簡単な規則(「簡潔に」「ファイルのパスを明確に」)
- Pi のドキュメントの場所(ハーネス自体について聞かれたときだけ読む)
- あなたの `AGENTS.md` など(プロジェクト・文脈)、スキルの名前と説明、作業フォルダ

システムプロンプトは、**名前つきのセクション**の集まりです。拡張が、`sections` に、自分のセクションを足せます(このハーネスの `<harness>` がそうです。[04](04-instructions-and-output.md))。

## 4. 設定は、どこに置くか

### 4.1 2 つの場所
| 場所 | 名前 | 内容 |
|---|---|---|
| `~/.pi/agent/` | **エージェントディレクトリ**(ユーザー全体) | 自分の、すべてのプロジェクトに効く設定 |
| `<プロジェクト>/.pi/` | **プロジェクトの設定** | そのプロジェクトだけ。**信頼した後で**読み込まれる |

エージェントディレクトリは、環境変数 `PI_CODING_AGENT_DIR` で、**別の場所に切り替え**られます(試用に便利。[01](01-install-and-run.md))。
**優先順位:** プロジェクトの設定が、ユーザーの設定を上書きします(`settings.md`)。ただし、リソースの一覧(拡張・スキルなど)は、**合体**します。

### 4.2 「何を、どのファイルに」(`configuration.md`)
| やりたいこと | ユーザー全体 | プロジェクト |
|---|---|---|
| 設定(既定のモデル、ツール、要約など) | `~/.pi/agent/settings.json` | `.pi/settings.json` |
| **AI への指示(常に守ってほしいこと)** | `~/.pi/agent/AGENTS.md`(`CLAUDE.md` でも可) | プロジェクトの `AGENTS.md`(または `CLAUDE.md`)。親フォルダのものも読まれる |
| システムプロンプトを**丸ごと置き換える** | `~/.pi/agent/SYSTEM.md` | `.pi/SYSTEM.md` |
| システムプロンプトに**追記する** | `~/.pi/agent/APPEND_SYSTEM.md` | `.pi/APPEND_SYSTEM.md` |
| **拡張**(プログラム) | `~/.pi/agent/extensions/` | `.pi/extensions/` |
| **スキル** | `~/.pi/agent/skills/` | `.pi/skills/` |
| **プロンプトテンプレート**(`/名前` で呼ぶ定型文) | `~/.pi/agent/prompts/` | `.pi/prompts/` |
| テーマ(色) | `~/.pi/agent/themes/` | `.pi/themes/` |
| キー割り当て | `~/.pi/agent/keybindings.json` | — |
| モデル・接続先の追加 | `~/.pi/agent/models.json` | — |
| MCP サーバー | `~/.pi/agent/mcp.json` | `.pi/mcp.json` |
| ログイン情報(**秘密**) | `~/.pi/agent/auth.json` | — |

編集したあと、Pi の中で **`/reload`**(設定・キー割り当て・指示・拡張・スキル・テンプレート・テーマ・指示ファイルを再読み込み)。

**`/settings`** で、よく使う設定は、画面から変えられます。それ以外は、`settings.json` を直接編集するか、**Pi に頼んで編集させる**(公式がそう書いています)。`settings.json` の先頭に、次を書くと、エディタが補完・検証してくれます。
```json
{ "$schema": "https://pi.dev/schemas/settings.schema.json" }
```

### 4.3 プロジェクトの信頼(project trust)
プロジェクトの `.pi/settings.json`、`.pi/extensions`、`.pi/skills`、`.pi/SYSTEM.md` などがあるフォルダで Pi を起動すると、**「信頼しますか」と聞かれます**。信頼するまで、それらは読み込まれません(知らないリポジトリが、勝手にプログラムを実行するのを防ぐ)。
- 保存先: `~/.pi/agent/trust.json`。`/trust` で、決定を保存。
- 画面のない実行(`-p`、`--mode json/rpc`)では、聞けないので、既定では**読み込まない**。`--approve` / `--no-approve` で、明示できる。
- **`AGENTS.md` / `CLAUDE.md` は、信頼の対象外**で、常に読み込まれます(**中身は、信頼できない入力として扱う**ように、と公式が注意)。
- 重要: **信頼は、ツールの権限を制限しません。** 信頼したあとも、ツールは、Pi を起動したユーザーの権限で、何でもできます。

## 5. 「プログラムを書く」とき、どこに書くか

公式の「**いちばん弱い仕組みから、始める**」の表(`quickstart.md`)が、そのまま使えます。

| やりたいこと | 使うもの | 書く場所 | 難しさ |
|---|---|---|---|
| 常に守ってほしい指示を渡す | **`AGENTS.md`** | プロジェクトの直下、または `~/.pi/agent/` | とても易しい(文章だけ) |
| よく使う依頼文を、`/名前` で呼ぶ | **プロンプトテンプレート** | `~/.pi/agent/prompts/名前.md` | 易しい(Markdown) |
| 特定の作業の手順と、補助ファイルを渡す | **スキル** | `~/.pi/agent/skills/名前/SKILL.md` | 易しい〜普通 |
| **ツール・コマンド・イベントの処理を、プログラムで足す** | **拡張** | `~/.pi/agent/extensions/名前.ts`(または `名前/index.ts`) | 普通(TypeScript) |
| 画面の部品を作る | TUI | 拡張の中 | 難しい |
| 未対応のモデルサービスを、つなぐ | カスタムプロバイダ | 拡張の中 | 難しい |
| いくつかをまとめて、配る・入れる | **パッケージ** | `pi install npm:...` / `git:...` / パス | 普通 |

### 5.1 ルールの 3 分類と、置き場所の対応(このハーネスの考え方)
| ルールの種類 | 例 | 置き場所 |
|---|---|---|
| ③ 固定の指示(守られるかは、モデルしだい) | 日本語で書く | `AGENTS.md` / `APPEND_SYSTEM.md` / 拡張の `<harness>` セクション |
| ① 止める(強制) | `main` に push しない | **拡張**の `tool_call` イベント(`{ block: true }`) |
| ② 流れ(順序・条件) | 計画 → 検証 → レビュー → PR | **拡張**(状態を持つ、`agent_before_settle` など) |

**① と ② は、`AGENTS.md` では、実現できません。拡張(プログラム)が必要です。** これが、ハーネスを「作る」という意味です。

### 5.2 いちばん小さい拡張(動かして確かめよう)
公式の最小の例です(`extensions.md`)。`~/.pi/agent/extensions/hello.ts` に置きます。
```ts
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.on("session_start", async (_event, ctx) => {
    ctx.ui.notify("拡張を読み込みました", "info");
  });

  pi.registerCommand("hello", {
    description: "あいさつ",
    handler: async (args, ctx) => ctx.ui.notify(`こんにちは ${args || "world"}`, "info"),
  });
}
```
- 置いたら、`/reload`(または Pi を再起動)。`/hello` と打つと動く。
- 試すだけなら、`pi -e ./hello.ts`(置かずに、1 回だけ読み込む)。
- **拡張は、Pi と同じプロセスで、同じ権限で動きます。** 他人のものは、**中身を読んでから**使う。
- 公式のサンプルが `examples/extensions/` に、約 70 個あります(`permission-gate.ts`、`protected-paths.ts`、`confirm-destructive.ts`、`plan-mode/`、`todo.ts`、`subagent/`、`custom-compaction.ts`、`gondolin/`(サンドボックス)など)。**まず、読んで、真似る**のが、いちばん早いです。

### 5.3 スキルの最小の例
`~/.pi/agent/skills/commit-message/SKILL.md`:
```markdown
---
name: commit-message
description: 変更内容から、コミットメッセージを日本語で書く。コミットを作るときに使う。
---
# コミットメッセージ
1. `git diff --staged` を読む。
2. 1 行目に、変更の要約(50 文字以内)。空行のあと、理由を書く。
```
- 起動時に、**名前と説明だけ**が、システムプロンプトに入ります。本文は、**必要になったときだけ**読まれる。
- `/skill:commit-message` で、強制的に呼べる。
- **`description` が、いつ使われるかを決めます。** 「何をするか」と「いつ使うか」を、両方書く。
- 形式は、**Agent Skills の仕様**(Claude Code と、同じ `SKILL.md`)。

### 5.4 プロンプトテンプレートの最小の例
`~/.pi/agent/prompts/review.md`:
```markdown
---
description: ステージ済みの変更をレビューする
argument-hint: "[観点]"
---
ステージ済みの変更を、レビューしてください。観点: ${1:-正しさ、セキュリティ、エラー処理}
```
`/review` または `/review 並行処理` で、呼べる。**実行する処理は、持てません**(定型文だけ)。

## 6. 一から作る、おすすめの順序

初心者が、**確実に、1 段ずつ**進めるための順序です。各段で、**動くことを確かめて**から、次へ進みます。

| 段 | やること | 学べること |
|---|---|---|
| 0 | 使い捨てのディレクトリで、素の Pi を使う(`PI_CODING_AGENT_DIR=$HOME/pi-trial`) | 素の Pi の姿。**確認なしで、何でもできる**こと |
| 1 | `/login` と `/model` で、3 つのプロバイダを使えるようにする | 認証、モデルの切り替え |
| 2 | `AGENTS.md` に、日本語の指示を書く | **指示は、守られるが、保証はない**こと |
| 3 | `permission-gate.ts`(公式のサンプル)を、`extensions/` に置く | イベント `tool_call` と、ブロック |
| 4 | 自分で、`.env` への書き込みを止める拡張を書く | 拡張の書き方、テスト |
| 5 | プロンプトテンプレートと、スキルを 1 つずつ作る | 軽い仕組みと、拡張の使い分け |
| 6 | `tool_call` を、拡張で強化する(`git push` を止める、など) | 本格的なガード([03](03-guards.md)) |
| 7 | (必要になったら)計画・サブエージェント・ループ | [06](06-subagents.md)、[07](07-plan-and-loop.md) |
| 8 | **サンドボックス**(最後の壁) | `containerization.md`、Gondolin など |

**進め方のコツ:**
- **1 段ごとに、`git` でコミット**する(設定を、リポジトリで管理)。
- いきなり、全部入りを作らない。**足りなくて困ったものだけ**、足す。
- 困ったら、**Pi 自身に聞く**: Pi は、自分のドキュメントの場所を、システムプロンプトで知っています。「拡張の書き方を、ドキュメントを読んで教えて」と頼める。

## 7. このリポジトリの現状との関係
- すでに、段 0〜7 に相当するものが、**一通り作ってあります**(ガード、指示、モデル、サブエージェント、計画とループ、PR のゲート、要約)。**「一から作り直す」場合の、完成形の例**として、読めます。
- 作り直す場合は、**この章の順序で、1 段ずつ**進め、**詰まったところで、このリポジトリの該当する章**(03〜09)を、見ます。

## 8. 限界と注意
- この章は、**公式ドキュメント(1.5.2 に同梱)の要約**です。**Pi は更新が速く**、新しい版では、変わっている可能性があります。迷ったら、`node_modules/@earendil-works/pi-coding-agent/docs/` の原文を見る(Pi 自身に読ませてもよい)。
- 上の例のコードは、公式ドキュメントの最小例を元にしています。**5.2 の `hello.ts`、5.3、5.4 は、私が実際に Pi で動かして確かめてはいません**(構文は、公式ドキュメントの例と同じ形です)。
- `defaultTools` や `trust.json` の細かい挙動は、`settings.md`、`security.md` で確認してください。
